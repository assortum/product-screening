# Ozon Compliance Base

Статическая поисковая база для первичного товарного compliance-screening перед отбором ниш на Ozon.

## Текущее состояние

- импортировано 9 308 сочетаний `Основная категория → Категория → Тип товара`;
- 8 980 уникальных названий типов товаров;
- 30 основных категорий;
- регуляторные данные не присваиваются автоматически только по названию товара;
- проект рассчитан на GitHub Pages и не требует backend.

## Что делает интерфейс

- поиск по основной категории, категории, типу товара и загруженному ТН ВЭД;
- фильтр `ПОДХОДИТ / ПРОВЕРИТЬ / ИСКЛЮЧИТЬ / НЕ ПРОВЕРЕНО`;
- отдельные фильтры по действующей маркировке, будущей утверждённой маркировке и эксперименту;
- фильтр по декларации, сертификату, СГР, отказному письму и отсутствию обязательного подтверждения;
- подробная карточка товара;
- источники нормативных выводов;
- дата последней проверки;
- продуктовые деревья уточняющих характеристик;
- пересчёт сценария ТН ВЭД, Честного знака и документов после выбора характеристик;
- ссылка на конкретный товар через `?product=ID`.

## Архитектура данных

### `data/catalog.json`

Лёгкий поисковый индекс всех типов товаров. Не содержит повторяющейся тяжёлой compliance-информации.

```json
{"id":1,"mainCategory":"Автомототехника","category":"Мототехника","type":"Модуль для мотобуксировщика"}
```

### `data/compliance-summary.json`

Краткий индекс только для уже проверенных товаров. Нужен для быстрого поиска и фильтрации.

```json
{
  "123": {
    "result": "yellow",
    "markingCurrent": "no",
    "markingFuture": "no",
    "experiment": "yes",
    "documentFlags": ["refusal"],
    "tnvedCodes": ["3926909709"],
    "lastChecked": "2026-08-27"
  }
}
```

Товары, которых в этом файле нет, автоматически считаются `НЕ ПРОВЕРЕНО`.

### `data/compliance/details/XXXXX-XXXXX.json`

Подробные данные загружаются лениво при открытии карточки. Размер одного диапазона — 500 ID.

Пример файла: `data/compliance/details/00001-00500.json`.

```json
{
  "123": {
    "normalizedName": "...",
    "marking": {
      "current": {"status":"no"},
      "future": {"status":"no"},
      "experiment": {"status":"yes", "label":"Эксперимент", "date":"до 2026-08-31"}
    },
    "tnved": {
      "candidates": [
        {"code":"3926909709", "confidence":"средний", "description":"..."}
      ],
      "needsClarification": ["материал", "назначение"]
    },
    "documents": {
      "items": [],
      "refusalLetter": "Возможно после уточнения",
      "basis": "..."
    },
    "sourceIds": ["source-id"],
    "lastChecked": "2026-08-27"
  }
}
```

### `data/sources.json`

Единый реестр нормативных источников. Карточки ссылаются на ID источника, поэтому один URL не размножается по тысячам товаров.

### `data/rules/attributes.json`

Справочник характеристик: материал, возрастное назначение, электроника, пищевой контакт, медицинское назначение и т. п.

### `data/rules/products/XXXXX-XXXXX.json`

Деревья решений для конкретных типов товаров. В карточке показываются только те вопросы, которые действительно влияют на классификацию этого типа товара.

Пример:

```json
{
  "123": {
    "questionIds": ["material", "electric"],
    "scenarios": [
      {
        "label": "Неэлектрическое изделие из пластика",
        "when": {
          "material": {"eq":"Пластик"},
          "electric": {"eq":"no"}
        },
        "output": {
          "tnvedCandidates": [{"code":"3926909709"}],
          "documents": {"status":"none", "items":[]},
          "marking": {
            "current":{"status":"no"},
            "future":{"status":"no"},
            "experiment":{"status":"no"}
          },
          "result":"green"
        }
      }
    ]
  }
}
```

Этот пример показывает только формат данных, а не нормативную классификацию конкретного товара.

## Почему не один `products.json`

Полная карточка с нормативными источниками и сценариями может быть в десятки раз тяжелее исходного каталога. Поэтому:

1. при открытии сайта загружается только каталог;
2. краткие compliance-статусы используются для фильтров;
3. подробности конкретного товара загружаются только при открытии карточки;
4. правила выбора ТН ВЭД также загружаются по диапазону ID.

Это позволяет сохранить сайт статическим и нормально работать с базой существенно больше 9 308 строк.

## GitHub Pages

В репозитории уже предусмотрен workflow `.github/workflows/deploy-pages.yml`.

После размещения файлов в ветке `main` для репозитория нужно выбрать GitHub Pages с источником `GitHub Actions`. После каждого push сайт будет пересобираться автоматически.

Проект использует только относительные URL и поэтому работает как project site, например:

`https://<username>.github.io/<repository>/`

## Локальный запуск

Из корня проекта:

```bash
python -m http.server 8000
```

Открыть:

`http://localhost:8000/`

Нельзя открывать `index.html` через `file://`, так как браузер блокирует часть `fetch`-запросов к JSON.
